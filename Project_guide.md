# Python Forex Trading Bot — Project Guide

## 1. Project Overview

This project is a modular Python-based forex trading bot designed to analyze market data from MetaTrader 5 (MT5), identify trading opportunities using technical indicators and candlestick patterns, manage risk, and evaluate trading strategies through historical backtesting.

The initial development phase focuses on collecting historical market data, calculating indicators, generating trading signals, and backtesting the strategy. Automated order execution will remain disabled until the strategy has been thoroughly tested.

## 3. Directory and File Descriptions

### `config/` — Configuration

**`config/settings.py`**

Contains the central configuration for the trading bot, including the trading symbol, chart timeframes, indicator periods, risk parameters, and execution settings.

Keeping configuration separate from strategy logic makes it easier to modify the bot without changing multiple source files.

### `data/` — Historical Market Data

**`data/eurusd_h1.csv`**

Stores historical EURUSD one-hour (H1) candlestick data. This data is used to analyze price movements and simulate trades during backtesting.

**`data/eurusd_h4.csv`**

Stores historical EURUSD four-hour (H4) candlestick data. It is used primarily to identify the higher-timeframe market trend.

These CSV files are generated by `get_data.py`. They should contain timestamped OHLC data (open, high, low, and close), along with any additional fields returned by MT5.

### `src/` — Core Trading Logic

**`src/__init__.py`**

Marks `src` as a Python package. It can remain empty.

**`src/data_feed.py`**

Provides reusable functions for retrieving, validating, and preparing market data from MetaTrader 5.

**`src/indicators.py`**

Implements technical indicators, including the 20-period and 50-period exponential moving averages (EMA 20 and EMA 50).

**`src/patterns.py`**

Identifies candlestick patterns, such as bullish engulfing and bearish engulfing, that may be used to confirm potential trading opportunities.

**`src/strategy.py`**

Contains the trading strategy rules. It combines higher-timeframe trend information, lower-timeframe conditions, and candlestick confirmations to produce a BUY, SELL, or NO TRADE signal.

The strategy module identifies opportunities; it should not directly execute orders.

**`src/risk_manager.py`**

Calculates position sizes and evaluates risk-related constraints, such as the permitted risk per trade, stop-loss distance, and maximum exposure.

**`src/trade_manager.py`**

Manages trade-related decisions, including stop-loss placement, take-profit targets, trailing stops, and exit conditions.

The exact responsibilities of this module should remain separate from the strategy's signal-generation logic.

### `backtesting/` — Historical Strategy Testing

**`backtesting/__init__.py`**

Marks `backtesting` as a Python package. It can remain empty.

**`backtesting/engine.py`**

Simulates the trading strategy using historical candle data. It models entries, exits, stop-losses, take-profits, and trading costs according to the selected backtesting rules.

Signals must use only information available at the time they occur. For example, a signal confirmed at candle close should not receive an unrealistically favorable entry price from that same completed candle.

**`backtesting/report.py`**

Calculates and presents backtesting performance statistics, including net profit or loss, win rate, maximum drawdown, number of trades, and risk-to-reward performance.

### `execution/` — Order Execution

**`execution/__init__.py`**

Marks `execution` as a Python package. It can remain empty.

**`execution/mt5_executor.py`**

Contains the functions responsible for communicating with MT5 to submit, modify, and close orders.

Order execution must remain disabled during initial development and historical backtesting. Before enabling it, verify the active MT5 account and server, validate position sizing, and test all safety checks on a demo account.

### `tests/` — Automated Tests

**`tests/__init__.py`**

Marks `tests` as a Python package. It can remain empty.

**`tests/test_indicators.py`**

Tests indicator calculations to ensure that EMA values and other calculations behave as expected.

**`tests/test_strategy.py`**

Tests the trading strategy under predefined market conditions to verify that it generates the expected BUY, SELL, or NO TRADE signals.

### Root-Level Files

**`get_data.py`**

Connects to MT5, retrieves historical H1 and H4 candles, and saves them as CSV files in the `data/` directory.

The script should retrieve completed candles for historical analysis and verify that the intended MT5 account and server are connected before accessing data.

**`live_data.py`**

Connects to MT5 and monitors current market ticks, including bid and ask prices. It can be used to inspect live price updates and understand how market data arrives.

Monitoring ticks does not itself execute trades.

**`main.py`**

Acts as the main entry point for the project. It coordinates the appropriate modules to run data processing, indicator calculations, strategy analysis, backtesting, or other selected tasks.

**`requirements.txt`**

Lists the external Python packages required to run the project. It should contain package names and, where appropriate, version constraints rather than general project documentation.

**`.gitignore`**

Specifies files and directories that Git should ignore, such as Python cache files, virtual environments, local environment variables, and temporary output files.

**`PROJECT_GUIDE.md`**

Documents the project structure, the purpose of each module, and the intended development workflow.

## 4. Development Workflow

The project should be developed in the following order:

1. Configure the Python environment and install the required dependencies.
2. Connect to the intended MT5 demo account and retrieve historical H1 and H4 candles.
3. Validate the downloaded data and calculate the required indicators.
4. Implement and test candlestick-pattern detection.
5. Implement the trading strategy and verify its signals.
6. Develop the risk-management and trade-management logic.
7. Build the historical backtesting engine and performance report.
8. Review backtesting results, account for trading costs, and test robustness.
9. Only after sufficient validation, consider demo order execution with explicit safety controls.

## 5. Important Design Principles

- Keep strategy logic separate from order execution.
- Use completed candles when generating candle-close signals.
- Avoid look-ahead bias in historical backtesting.
- Include realistic spread, commission, and slippage assumptions where applicable.
- Calculate position size using the intended risk and stop-loss distance.
- Verify the active MT5 account and server before running scripts.
- Never store account passwords or other credentials directly in source code.
- Treat backtesting results as estimates, not guarantees of future profitability.

## 6. Current Development Status

The initial goal is to establish reliable data collection and historical backtesting. Live tick monitoring is intended for market-data observation, not automatic trading.

The project should progress to demo execution only after its data pipeline, strategy rules, risk controls, and backtesting behavior have been tested.
